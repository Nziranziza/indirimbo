# Indirimbo

Kinyarwanda church hymnal app — browse and search songs from Agakiza and Gushimisha playlists.

## Tech Stack

- Expo 55 + React Native 0.83 + TypeScript (strict)
- Expo Router (file-based routing in `app/`)
- React Native Web for web export
- Fuse.js for fuzzy search
- AsyncStorage for local persistence (favorites, settings)

## Project Structure

- `app/` — screens and layouts (Expo Router file-based routing)
- `app/(tabs)/` — bottom tab navigation (home, search, favorites, settings)
- `components/` — reusable UI components
- `constants/` — song data, theme, typography, playlists
- `contexts/` — React contexts (songs, theme)
- `hooks/` — custom hooks (colors, theme, hydration)
- `utils/` — helpers (lyrics parsing, storage)
- `scripts/` — build scripts for web deployment (sitemap, song pages)
- `tools/` — song data extraction pipeline

## Commands

- `npm start` — start Expo dev server
- `npm run web` — start web dev server
- `npm run build:web:gh-pages` — full web build with SEO pages and sitemap
- `npm run lint` — run ESLint

## Path Aliases

`@/*` maps to the project root (e.g., `@/components/`, `@/constants/`).

## Song Data

Song lyrics are in `constants/agakiza-songs.ts` and `constants/gushimisha-songs.ts`. These are generated by the `tools/` pipeline — don't edit them by hand.

## Coding Conventions

### General
- TypeScript strict mode — no `any`, always type props and function signatures
- Use `interface` for component props, `type` for unions and aliases
- Named exports for components and hooks (no default exports except route screens)
- Route screen files in `app/` use `export default function`
- Prefer `const` over `let`; never use `var`
- Use optional chaining (`?.`) and nullish coalescing (`??`) over manual null checks
- Avoid type assertions (`as`) — prefer type guards and narrowing
- Use `readonly` for props and data that shouldn't be mutated

### Naming
- Files: `kebab-case.tsx` (e.g., `song-list-screen.tsx`, `use-colors.ts`)
- Components: `PascalCase` (e.g., `SongListScreen`, `ThemedText`)
- Hooks: `useCamelCase` prefix (e.g., `useColors`, `useThemeColor`)
- Constants/keys: `UPPER_SNAKE_CASE` (e.g., `FAVORITES_KEY`, `HEADER_MAX_HEIGHT`)
- AsyncStorage keys: `@indirimbo:snake_case` prefix
- Event handlers: `handle` prefix (e.g., `handleSongPress`, `handleSetThemePreference`)
- Booleans: `is`/`has`/`should` prefix (e.g., `isLoading`, `isScrollable`)

### File Size & Component Structure
- **Screen files (`app/`) should not exceed 300 lines.** If a screen grows beyond that, extract sections into components under `components/`.
- **Component files (`components/`) should not exceed 200 lines.** Split into smaller sub-components in the same directory or `components/ui/`.
- **One primary component per file.** Small, tightly-coupled helper components (e.g., a list item used only by that list) may live in the same file, but should be defined *above* the main component and wrapped in `React.memo` if they receive props.
- **Extract inline JSX blocks into named components** when they exceed ~30 lines or contain their own logic/state. Inline anonymous functions in JSX that span multiple lines should become named components or at least extracted `renderX` functions.
- **Extract repeated patterns into reusable components.** If the same JSX structure (e.g., a settings group card, a nav link row) appears 3+ times, it should be a component.
- **Hooks logic that exceeds ~30 lines should be extracted into a custom hook** in `hooks/` (e.g., `useSongNavigation`, `useKeepAwake`, `useSectionPositions`).
- **Style objects should live at the bottom of the file** in a single `StyleSheet.create()` call. If styles exceed ~80 lines, consider whether the component itself is too large.

### Components
- Use `ThemedText` and `ThemedView` instead of raw `Text`/`View` for theme support
- Get colors via the `useColors()` hook, not hardcoded values
- Use `StyleSheet.create()` at the bottom of the file for styles
- Use `react-native-reanimated` for animations (shared values, `useAnimatedStyle`)
- Wrap callbacks in `useCallback` when passed as props
- Use `useMemo` for expensive computations derived from props/state
- Prefer functional components — no class components
- Destructure props in function signature
- Use `React.memo` for list item components and components that re-render frequently with the same props
- Define shared/reused types (e.g., `Song`) in a dedicated types file or in `constants/` — don't redeclare the same interface across multiple files
- Avoid deeply nested ternaries in JSX — extract into variables or early returns
- Avoid inline styles for anything beyond single dynamic properties — use `StyleSheet` instead

### React Native & Expo
- Use `expo-router` for all navigation — no manual stack navigators
- Use `expo-*` packages over bare React Native equivalents when available
- Use `Platform.OS` checks for platform-specific logic, or `.web.ts`/`.ios.ts` file extensions for platform-specific files
- Use `useSafeAreaInsets()` for safe area handling — don't hardcode status bar heights
- Use `expo-haptics` for tactile feedback
- Use `FlatList` for long lists — never map over large arrays in JSX
- Set `removeClippedSubviews`, `maxToRenderPerBatch`, and `windowSize` for list performance
- Use `expo-image` over `Image` from react-native for better caching and performance

### Hooks & State Management
- Use React Context for global state (theme, songs)
- Keep state as local as possible — lift only when needed
- Use AsyncStorage for persistence — wrap in typed helper functions in `utils/storage.ts`
- Async functions should handle errors with try/catch and log via `console.error`
- All `useEffect` hooks must have explicit dependency arrays — no missing deps, no `eslint-disable`
- Effects that only run on mount should use `[]` and include a cleanup function if they set up subscriptions/timers
- Don't call hooks conditionally or after early returns — all hooks must be called in the same order every render
- Prefer `useFocusEffect` over `useEffect` for data loading on screen focus
- Custom debounce logic should be extracted into a `useDebounce` hook rather than repeated inline

### Imports
- Always use `@/` path alias for project imports
- Group imports: external packages first, then `@/` project imports

### Performance
- Use `FlatList`/`SectionList` for any list that could exceed ~20 items — never `.map()` in JSX for long lists
- Always set `removeClippedSubviews`, `maxToRenderPerBatch`, and `windowSize` on large lists
- Use `keyExtractor` with stable, unique keys — avoid array index as key when list items can reorder
- Heavy computations (filtering, sorting, searching) must be wrapped in `useMemo`
- Use `React.memo` on list item components to prevent unnecessary re-renders
- Avoid creating new objects/arrays/functions inside render — hoist to `useMemo`/`useCallback` or module scope
- Use `expo-image` over `Image` from react-native for better caching and performance

### Cross-Platform
- Always consider web, iOS, and Android — test platform-specific behavior
- Use `Platform.select()` or platform file extensions for divergent implementations
- Avoid platform-only APIs without a fallback

### Code Quality
- No commented-out code in committed files — delete it, git has history
- No magic numbers — extract into named constants with clear meaning
- No `console.log` in committed code — use `console.error` only for actual error handling
- Avoid `any` type — if the type is complex, define it explicitly or use `unknown` with narrowing
- Keep function signatures clean — if a function takes more than 3 parameters, use an options object
- Avoid nested callbacks deeper than 2 levels — extract into named functions
- All promises must be handled — either `await` them or attach `.catch()`
